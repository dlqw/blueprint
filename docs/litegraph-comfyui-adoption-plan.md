This plan tracks how Blueprint IDE will keep the current React/Tauri product path while adopting proven graph-editor architecture ideas from LiteGraph, mature workflow interactions from ComfyUI, and established editor ergonomics from Unreal Engine Blueprint.

## Direction

Keep the current React frontend and Tauri desktop shell. Do not port the UI to Vue. Do not copy ComfyUI's product model wholesale. Instead:

- Adopt LiteGraph's architectural separation: viewport transform, graph model, canvas layers, event processing, and rendering lifecycle.
- Adopt ComfyUI's workflow ergonomics: compact canvas tools, selection toolbox, actionbar/run controls, minimap/link visibility, reroute conventions, and settings.
- Adopt ComfyUI frontend's visual style more directly: dark neutral canvas-first workspace, compact top menu/actionbar density, bottom/right canvas command affordances, floating panels, subtle borders, restrained accents, icon-forward controls, and operational rather than marketing layout.
- Default the product UI to Chinese and route all user-visible strings through non-hardcoded I18N catalogs with fallback and future language switching.
- Add modern theme configuration and switching through semantic CSS tokens, persisted editor preferences, import/export-ready theme data, and runtime theme application without mutating graph data.
- Style graph nodes after ComfyUI: compact dark node bodies, clear title bars, slot/pin colors, selected/error/bypass states, widget/input rows, and readable minimap representation, while keeping Blueprint node ids, templates, ports, links, and compiler bindings unchanged.
- Adopt UE Blueprint's editor expectations: shortcuts, pin gestures, comments, breakpoints, searchable graph structure, and graph/function/macro organization.
- Preserve Blueprint IDE's file contracts: `.bsln`, `.bproj`, `.bpgraph`.
- Keep TypeScript-oriented compilation/runtime semantics distinct from ComfyUI's prompt queue.

## Current Requirements

The latest plan update adds three explicit execution targets:

- Default the UI to Chinese, and route all user-visible strings through non-hardcoded I18N catalogs with fallback and language switching.
- Support modern theme configuration and switching through semantic theme data, runtime application, and persisted editor preferences.
- Restyle graph nodes toward ComfyUI node visuals while preserving Blueprint graph semantics, compiler bindings, and file formats.

## Product Principles

| Principle | Meaning |
| --- | --- |
| Graph first | The first screen remains a usable graph editor, not a launcher or marketing surface. |
| ComfyUI-style shell | The React UI should read like a ComfyUI-style graph workspace: dark, compact, canvas-dominant, floating-control oriented, and visually quiet. |
| Chinese-first I18N | The default language is Chinese, and user-visible text must come from localization catalogs rather than hardcoded component strings. |
| Theme by tokens | Theme changes flow through semantic tokens and persisted user preferences, not raw per-component color rewrites or graph-file data. |
| ComfyUI-like nodes | Nodes should visually resemble ComfyUI nodes while preserving Blueprint IDE's TypeScript templates, port contracts, runtime traces, and file formats. |
| Mature gestures over novelty | Prefer UE/ComfyUI-proven interactions over custom gestures unless the TypeScript Blueprint model requires them. |
| No event ambiguity | A pointer event belongs to exactly one interaction state or overlay surface. |
| Command surfaces stay reachable | If a toolbar action moves or hides under responsive layout, it must remain available through a command palette, menu, shortcut, or canvas tool. |
| UI settings are not graph data | User preferences such as grid visibility, link render mode, minimap, and actionbar placement must not mutate `.bpgraph` semantic data. |
| Incremental extraction | Extract architecture from the current React editor before considering larger rendering or data-model changes. |
| Test the interaction contract | Every new gesture, toolbar, or overlay must have at least one regression test or explicit manual verification checklist. |

## Non-Goals

| Non-Goal | Reason |
| --- | --- |
| Vue migration | Framework migration does not solve the current interaction and architecture gaps. |
| Vue/Pinia/PrimeVue reimplementation | ComfyUI frontend is the visual and interaction reference, but Blueprint IDE remains a React/Tauri application. |
| Direct ComfyUI product clone | Blueprint IDE targets TypeScript Blueprint projects, not image-generation prompt workflows. |
| Hardcoded user-facing UI strings | Default Chinese and language switching require catalog-backed strings; ids, schema keys, code symbols, and file-format fields remain non-localized. |
| Python custom-node manager | Our equivalent should be a TypeScript template/package registry. |
| Immediate full LiteGraph engine replacement | Adopt architecture first; replace rendering engine only if profiling proves it necessary. |
